# ИИ-разбор Orienta через ProxyAPI

## Что делает интеграция

После теста и всех пяти этапов ученик открывает профкарту и нажимает «Получить ИИ-разбор». Клиент сначала сохраняет ответы, затем вызывает POST /api/ai-summary с номером сохранённой версии и временной сессией ученика. Сервер берёт ответы из собственной базы; произвольные промпты от клиента не принимает.

Ответ GPT-4o mini содержит наблюдения по ответам, 2–3 направления с объяснениями и бесплатными практическими пробами, следующий шаг на неделю. Это гипотезы для исследования, без диагноза или заявления о профессиональной пригодности. Провайдер возвращает JSON по схеме; сервер проверяет форму и ограничения длины. Неоконченный или некорректный ответ не показывается.

Готовый текст хранится в YDB с отпечатком содержательных ответов, модели и версии инструкции. После получения он входит и в обычное сохранение прогресса. Если ответ HTTP потерян, повторный запрос использует серверный кэш. Имя героя, движение по интерфейсу, время просмотра урока и старый ИИ-текст на отпечаток не влияют. Смена ответов требует нового разбора. Кэш разделён по ученикам.

Одновременные запросы защищены записью в базе, поэтому несколько экземпляров функции не запускают один разбор одновременно. Ожидание провайдера — до 18 секунд, автоматических платных повторов нет. После ошибки выдерживается минута. После генерации снова проверяются доступ ученика, сессия и актуальность ответов.

## Настройки для включения

Код сам по себе не включает платные запросы. Нужны две настройки только на ученической Cloud Function:

- ORIENTA_AI_ENABLED=true
- ORIENTA_AI_API_KEY — отдельный ключ Orienta из существующего аккаунта ProxyAPI, с доступом только к openai/gpt-4o-mini и разовым бюджетом пилота.

Ключ не помещать в GitHub, VITE_*, браузер, скриншоты или переписку. Учётную запись «Резюме Готово» и её Timeweb-сервис запускать не требуется. Автопополнение не включать.

Адрес закреплён в серверном коде: https://api.proxyapi.ru/v1/chat/completions, модель openai/gpt-4o-mini, максимум 1800 выходных токенов. Используется действующий единый API, а не старый адрес из резервной копии ResumeGotovo.

Пределы в базе: 100 зарезервированных запросов на ключ за весь пилот, 3 на ученика за сутки UTC. Неудачные и неоднозначные попытки тоже расходуют резерв; это консервативный предел числа попыток, а не расчёт рублей. Возврат готового кэша лимит не расходует. При исчерпании лимита увеличение должно быть осознанным изменением серверной конфигурации/кода; смена ключа создаёт новый общий счётчик.

## Порядок публикации

1. Выполнить npm test, npm run build и npm run build:server; пройти браузерные сценарии. Проверки используют синтетические ответы и имитацию провайдера, без платных запросов.
2. Создать отдельный ключ с разовым бюджетом в Safari и передать его прямо в серверные настройки. Текущее состояние баланса проверить отдельно.
3. Загрузить новую dist-server/function.js с package.json в существующую ученическую функцию. Сохранить её текущие параметры YDB, сервисный аккаунт и разрешённый origin. Закрытую операторскую функцию и её права не менять.
4. Обновить только enum маршрутов действующего шлюза: добавить ai-summary к health, session, progress. Сохранить текущий ID функции, invoker-аккаунт, tag orienta-pilot, формат события 1.0 и таймаут 35 секунд. Таймаут функции остаётся 30 секунд.
5. Проверить синтетическим аккаунтом вход, запрет анонимного запроса, один реальный разбор и повтор из кэша без второго обращения к провайдеру.
6. Опубликовать frontend на существующем Timeweb-приложении. Достаточно прежнего VITE_PROGRESS_API_URL. Отдельный VITE_AI_PROXY_URL и старые Google-переменные больше не используются. Кнопка доступна только если вошедшему ученику сервер сообщил aiAvailable=true.
7. Проверить в Safari появление разбора, восстановление в другом сеансе, сохранение уроков и отсутствие ключа в клиентском JavaScript.

При отказе провайдера профкарта и уроки продолжают работать. Для отключения ИИ снять ORIENTA_AI_ENABLED на ученической функции; повторный вход или обновление страницы скрывает кнопку. Старые сохранённые разборы остаются в прогрессе.

## Обработка данных

База прогресса остаётся в России. ИИ-запрос через ProxyAPI/OpenAI обрабатывается за пределами России. Кнопка сообщает об отправке перед действием ученика. Системные поля с именем, ником, контактами, кодами и ID ученика не отправляются; свободный текст дополнительно очищается от ссылок, почты и российских телефонов. Такая очистка не гарантирует анонимность: имена и название школы в свободных ответах должен убрать сам участник/наставник до отправки. Не записывать ответы и ключи в журналы.
