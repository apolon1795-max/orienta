# Бесплатный вход и платный курс: проверка 15 ноября 2026

## Последнее направление владельца

Сначала сделать бесплатный стартовый тест. Затем заняться оплатой через ЮKassa. Не закрывать прежний пилотный курс и не объявлять прежние коды оплаченными. Следующие два часа: только локальная работа, без публикаций и отправки третьим сторонам. Поэтому нижеследующая архитектура платёжного барьера остаётся следующим этапом, а не результатом текущего выпуска.

Реализован FreeEntry: исходные TestView и GuideView переиспользованы без изменения вопросов, баллов, архетипов и иллюстраций. Пять исходных ситуаций плюс персонаж/имя/сюжет/свиток/гайд. Вводная без логина, ответов на сервер и ИИ. Отдельное sessionStorage; не подмешивается в учебный профиль. Переход в прежний пилот по #course и существующему личному коду; эквайринг и серверные права пилота не изменены. Онлайн-оплата явно помечена как ещё не подключённая.

Это НЕ защищённый платный курс: lazy-загрузка App не является защитой публичной JS-сборки. Подготовленный entitlement-модуль пока не подключён.

Основание: владелец хочет открыть вводную и определение архетипа всем; пять этапов курса только после оплаты. Исходный код: 0d52026. Эта ветка не публиковалась.

## Что есть сейчас

- App.tsx:330 показывает ProgressAccess вместо всего приложения без личного кода при настроенном API. Бесплатного публичного входа нет.
- Личный код подтверждает личность профиля, но не оплату. server/api.mjs не проверяет права на курс.
- Материалы курса импортируются в CourseView/FinalStages, а видео поступают через VITE_LESSON_* в публичную сборку. Блокировка кнопки или lazy import не защитят содержимое.
- services/progress.ts использует данные курса для нормализации. Для исключения платного содержимого из сборки нужно разделить публичные идентификаторы/валидацию и тексты заданий.

## Предлагаемая реализация

1. Отдельный публичный маршрут: вводная, игровой тест, архетип и его описание. Без имени, телефона, почты и вызова ИИ. Прогресс только в этом браузере, с понятным предупреждением. Это игровой результат, не валидированная диагностика.
2. После результата: предложение полного курса. Вход в оплаченный курс отдельной кнопкой. До выбора провайдера никаких кнопок с ложным успешным платежом. Возможен первый запуск с ручной проверкой реального платежа и выдачей личного кода.
3. Право на курс хранится отдельно от пользовательского прогресса в серверной БД. Код сам по себе права не даёт. Резервная копия, localStorage и параметры URL не могут его назначить.
4. Сервер проверяет право перед выдачей материалов, сохранением ответов платной части и ИИ-разбором. Повторно проверяет его после долгой генерации. При недоступности проверки не открывает новый платный контент. Возврат/отзыв доступа вступает в силу и для уже выданной сессии.
5. Перенести платные тексты и ссылки видео из публичной сборки в авторизованный endpoint. Сам видеохостинг также должен ограничивать просмотр; одной скрытой ссылки недостаточно. Уже выданный пользователю контент невозможно гарантированно отозвать с его устройства.
6. Переносить бесплатный результат в оплаченный профиль только по явному подтверждению, не затирать существующие ответы. Выход из профиля не должен показывать ответы предыдущего ученика.
7. Подключить эквайринг после выбора провайдера: проверенный серверный webhook, сумма/валюта/заказ/статус, идемпотентность, возвраты. Возврат в браузер после оплаты не считается подтверждением.

## Что подготовлено в этой ветке

server/course-access.mjs: изолированный серверный примитив права доступа с проверкой активного ученика и optimistic concurrency для защиты от устаревшего повторного разрешения после отзыва. Запись содержит только непрозрачную ссылку на проверенный платёж, без реквизитов. Публичного endpoint для выдачи прав нет. Модуль намеренно пока НЕ подключён к живым маршрутам: неполный шлюз нельзя выдавать за готовую защиту.

tests/course-access.test.mjs: два синтетических теста покрывают отсутствие права по коду, поддельное paid=true в прогрессе, выдачу, отзыв, устаревшую выдачу, отключённого ученика и неверные входные данные. Это не end-to-end тест всего freemium-сценария.

## Решения до публикации

- Цена, длительность доступа и способ приёма оплаты. Без этих решений можно закончить техническую границу и бесплатный маршрут, но не реальную покупку.
- Что делать с существующими кодами пилота: не объявлять всех оплатившими автоматически. Нужен подтверждённый список доступа.
- Условия обработки данных детей и ИИ: бесплатный тест не должен отправлять ответы во внешний ИИ. В текущем коде дополнительный разбор курса использует ProxyAPI/OpenAI; он не является локальной обработкой в РФ.

## Приёмочные проверки полной реализации

Бесплатный тест без кода; повторный заход/перезапуск; открытие URL курса без оплаты; поддельная оплата в браузере и в backup; ответы платной части прямым API; отсутствие платного контента/ссылок в JS сборке; платёж в ожидании/ошибка/повтор webhook; отзыв в активной сессии; сбой API; сохранение данных оплаченного профиля при переносе теста; выход и вход другого ученика; отсутствие реальных персональных данных в тестах.

Дополнительная проверка параллельной задачи: в другом проекте владельца «Резюме готово» найдена интеграция ЮKassa, не Prodamus. Это не подтверждает выбор или подключение магазина для Orienta. Не переносить существующий callback без изменений: для Orienta необходимо проверять сумму, валюту и привязку платежа к своему заказу и продукту, а не только статус. Общий callback работающего магазина не менять.
