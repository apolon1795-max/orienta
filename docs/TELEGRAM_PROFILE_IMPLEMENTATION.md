# Единый профиль Ориенты: браузер и Telegram

## Что подтверждено

В исходниках `apolon1795-max/orienta-landing/index.html` опубликован бот `https://t.me/mir_orienta_bot`. Это подтверждает название, но не владение ботом и не его текущую конфигурацию.

Существующая серверная модель: `learner:<uuid>`, `code:<sha256>`, `session:<sha256>`, `progress:<uuid>`. Прогресс хранится в YDB, с revision/CAS. Браузерный ORI-код уже является секретом входа. Telegram CloudStorage и имя пользователя не должны становиться новым источником истины.

## Предлагаемый первый сценарий

1. Пользователь проходит бесплатное введение локально и может отдельно подтвердить перенос в уже существующий серверный профиль по ORI-коду. Самостоятельная регистрация подготовлена под отдельным серверным флагом. Новый профиль имеет kind=free: API не разрешает запись ответов курса и запросы ИИ без серверного разрешения. Старые пилотные коды сохраняют прежние права, это не доказательство оплаты. Материалы курса всё ещё входят в публичный JS, защищённой доставкой платного контента это не является.
2. На другом браузере входит существующим личным ORI-кодом. Код показывается/копируется только при осознанном действии, не включается в ссылки или аналитику.
3. В Telegram открывает Mini App того же бота. Если Telegram ещё не связан, выбирает «У меня уже есть профиль», входит тем же ORI-кодом и подтверждает «Связать этот профиль с Telegram».
4. Сервер проверяет browser session и свежую криптографически подписанную Telegram initData; привязывает Telegram ID к существующему learnerId. Никакого поиска по имени/username.
5. При следующих входах из Mini App сервер проверяет новую initData, получает тот же learnerId, выдаёт обычную сессию. Прогресс читается через существующий `/progress`.
6. Если на устройстве есть несохранённые ответы, перед загрузкой серверного результата показывается выбор. Не затирать серверный прогресс локальным автоматически.

## Подготовленный код

- `server/telegram-auth.mjs`: `verifyTelegramInitData`, `consumeTelegramProof`.
- `server/telegram-link.mjs`: `linkTelegramIdentity`, `resolveTelegramLearner`.
- `tests/telegram-auth.test.mjs`, `tests/telegram-link.test.mjs`: 12 тестов (подпись/изменение полей, срок, replay, параллельные привязки, частичные записи, отключённый профиль).

Код интегрирован в API, клиент и шаблон gateway локальной ветки, но не опубликован и не включён в рабочем окружении. Реальные токены не использовались. Проверка HMAC соответствует Telegram Mini Apps, не Telegram Login Widget.

## Интеграция API

- `POST /telegram-session {initData}`: verifier → lookup обеих сторон → consume durable proof → повторная проверка active → выдача обычной server session + snapshot. Несвязанному аккаунту вернуть специальный статус, не создавать дубликат автоматически.
- `POST /telegram-link {initData}`: действующая bearer-сессия после входа по ORI-коду (не Telegram) → явное UI-подтверждение → verifier → consume proof → link с learnerId исключительно из сессии. Не принимать learnerId из body.
- Секрет существующего бота только в server env/секрет-хранилище, никогда `VITE_*`, source, логи или клиентский JS. При отсутствии секрета feature выключена и UI не обещает вход.
- Gateway должен пропустить новые маршруты, CORS разрешает только существующий app origin. При использовании cookies понадобятся отдельные CSRF/SameSite меры.
- Telegram ID хранится минимально в виде хешированного ключа subject; имена/фото для входа не нужны. ORI-коды и bearer/initData нельзя логировать.

## Ограничения и отказоустойчивость

Одноразовая proof после потери ответа не переиспользуется: приложение просит переоткрыть Mini App. Для бесшовного retry позднее нужен отдельный идемпотентный exchange, связанный с конкретной сессией/запросом; нельзя просто игнорировать replay.

В текущем store есть CAS одного ключа, а не атомарная операция двух ключей. Поэтому привязка записывает две стороны и авторизация работает только при их совпадении. Прерванную запись можно повторить с той же парой, но конфликтующие частичные резервирования намеренно не удаляются и не отдаются другому человеку. Для массового запуска предпочтительна транзакционная привязка в native YDB и процедура исправления/отвязки с повторной авторизацией.

Ключи replay следует удалять регламентной очисткой только после expiresAt и запаса на clock skew; не удалять валидные proof. Для Telegram включён общий CAS-счётчик по доверенному IP/минуте (30 попыток); для регистрации по IP/суткам (20 новых кодов). Это базовая защита, не полноценная антибот-система; распределённый спам возможен. Нужны мониторинг и ограничение бюджета ресурса перед массовым запуском.

## До публикации

1. Подтвердить владение/настройку существующего бота и Menu/Main Mini App URL, не менять его молча.
2. Подключить серверный секрет безопасным способом и явно согласовать требуемую конфигурацию.
3. Интегрировать API и gateway, проверить отсутствие доступа к платным данным через новый free login.
4. Тест: профиль браузера → архетип → связать Telegram → результат совпадает → пройти шаг в Telegram → браузер получает новый revision.
5. Тест: два разных аккаунта, подмена Telegram ID/неподписанные данные/старый initData/повторное использование/отключённый профиль → доступ запрещён; локальные ответы одного пользователя не попадают другому.

Источник протокола: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app

## Реализованный браузерный переход

Кабинет вводной ведёт в #profile на том же сайте. После входа по существующему ORI-коду пользователь отдельно подтверждает отправку архетипа/псевдонима/хода теста в свой YDB-профиль. Существующий результат или начатый тест профиля не заменяются. Прогресс курса сохраняется. Статус успешной записи берётся из ProgressSync, а не из наличия localStorage.

Telegram включается только парой ORIENTA_TELEGRAM_ENABLED=true и серверным ORIENTA_TELEGRAM_BOT_TOKEN. /health сообщает возможность; без неё кнопки не показываются. Официальный SDK Telegram загружается только после нажатия соответствующей кнопки. Секреты и реальные идентификаторы в тестах не используются. Новая регистрация включается отдельно через ORIENTA_FREE_REGISTRATION_ENABLED=true и по умолчанию выключена. Оплаты нет. Вход с телефона/ПК по существующему коду работает и без Telegram.

## Бесплатная саморегистрация

POST /register включается серверным флагом. Браузер через crypto.getRandomValues создаёт 128-битный ORI-код, показывает его до регистрации и требует подтверждение сохранения кода и отправки данных. Запрос передаёт code и consent; IP берётся только из gateway metadata. Сервер хранит hash кода и технический learnerId; имя/почта/телефон не нужны. Сначала создаётся неактивная запись, затем код, активация последняя. Повтор с тем же кодом восстанавливает прерванную операцию, отозванный/чужой код не перезаписывается.

После регистрации обычный /session открывает тот же профиль. Архетип переносится отдельно. Потеря кода без связанного Telegram означает потерю доступа; автоматического восстановления по ФИО или почте нет. Не распространять коды и не использовать их в URL.

До публичного включения нужны утверждённые политика приватности, возрастные условия и применимый процесс согласия для детского сервиса. Текущий checkbox описывает техническую отправку, не является проверкой возраста или подтверждением согласия законного представителя. Реальные пользовательские регистрации и Telegram-секреты в ходе разработки не создавались.

## Проверка и порядок выкладки этой версии

- 91 автоматический тест: в том числе настоящие локальные HTTP-клиенты регистрации/сохранения/второго устройства; Telegram проверен синтетически, без реального бота.
- TypeScript, SSR компонентов, сборка frontend и Yandex function проходят.
- В браузере опубликованного сайта проверен прежний хаб. Новые регистрация/привязка Telegram в настоящем браузере ещё не приняты. Это не утверждение о готовом production-профиле.
- Сначала развернуть совместимый backend и gateway с новыми маршрутами, оставив оба флага выключенными. Затем frontend: он ожидает courseAvailable от backend; старый backend этот признак не сообщает и новый клиент закроет курс даже пилотным аккаунтам.
- Проверить старый код и сохранение, затем включать регистрацию только после проверки приватности/возрастных условий. Telegram включать отдельно после настройки существующего бота и безопасного server-only секрета. Не менять/создавать admin credentials.
- Отказаться от прямого публичного хранения платных материалов в bundle до коммерческого запуска; нынешний API-gate не скрывает исходный учебный контент из JS. Оплата ЮKassa остаётся отдельной задачей.

## Новая отдельная ветка серверной доставки курса

Следующая версия заменяет публичный импорт App на облегчённый ProfileShell. CourseView/FinalStages, вопросы, разборы и их зависимости больше не входят в dist/assets. scripts/build-protected-course.mjs собирает один самодостаточный ES-модуль с CSS только в памяти; scripts/build-server.mjs встраивает его в серверную функцию. Заглушка course-artifact.mjs в исходниках возвращает null и без штатной серверной сборки выдача курса закрыта.

GET /course-content проверяет bearer-сессию, active и право курса на каждом запросе. Новые kind=free требуют серверной verified_payment-записи; прежние пилотные записи сохраняют старые права без объявления их оплаченными. Ответ no-store. Курс загружается через авторизованный fetch и Blob import в отдельный React root. CSP целевого хостинга должен допускать этот механизм; настройки CSP автоматически не менялись. Реальные уроки задаются только серверными ORIENTA_LESSON_N_VIDEO/CAPTIONS, не VITE_*.

95 тестов и build-corpus scan прошли: все строки вопросов QUIZ_DATA и HOLLAND_QUESTIONS отсутствуют в публичной сборке, в backend пакет присутствует. Browser E2E ключевого пути пройден на временном same-origin API с синтетическими данными: бесплатная регистрация → перенос архетипа → reload → вход другой вкладкой; пилотный код → авторизованный Blob-модуль → хаб → список пяти этапов со статусом сохранения. Обнаруженные fetch-binding, process/JSX runtime ошибки исправлены. Старый хаб на Timeweb не обновлялся. Скрипт tests/cloud-browser.mjs адаптирован, но в этой среде запуск Chromium напрямую недоступен.

Политика защиты ограничена дальнейшей выдачей. Репозиторий apolon1795-max/orienta подтверждён GitHub API как public, исходники уже доступны; перед продажами отдельно согласовать закрытый репозиторий и очистку старых публичных сборок. Ранее скачанное отозвать нельзя. Ссылки видео после выдачи авторизованному пользователю пересылаемы без отдельной защиты провайдера. Платёжный webhook/ЮKassa по-прежнему не подключены.


Браузерная приёмка не включает реальный Telegram, реальные видео, платёж и продовую базу. QA store был временным, с фиктивными профилями. В prod ничего не включалось. Репозиторий остаётся public по последнему указанию владельца, поэтому глобальная приватность ранее опубликованных материалов не обеспечивается.
