# Пилот Orienta: размещение, уроки и прогресс

## Выбранная схема

Аудитория — школьники в России. Сайт остаётся в существующем приложении Timeweb App Platform, ответы и прогресс хранятся в YDB Serverless региона Россия, видео — в Kinescope. Ученическая Cloud Function работает через API Gateway; отдельная закрытая функция выдаёт коды и выгружает результаты. Ученику нужен код наставника; регистрация по телефону и платные СМС не используются.

В Safari 3 ноября 2026 подтверждено существующее приложение Orienta: https://apolon1795-max-orienta-c425.twc1.net. На дашборде указаны списания 0 ₽/мес и прежний коммит 3f6f664. В разделе баз данных Timeweb ресурсов не найдено. Изменение ветки в PR само по себе не обновляет этот сайт.

По текущему free tier Yandex Cloud каждый месяц не оплачиваются: 1 ГБ данных и 1 млн единиц запросов YDB, 1 млн вызовов функций и 10 ГБ×час выполнения, 100 тыс. запросов API Gateway. Это позволяет рассчитывать на нулевые расходы для небольшой группы, но не является фиксированным бесплатным тарифом: лимиты общие для платёжного аккаунта, превышение тарифицируется. Домен и Kinescope считаются отдельно. Бюджетное уведомление не является жёстким ограничителем расходов. Владелец подтвердил создание отдельных ресурсов Orienta и оплату возможного превышения бесплатных лимитов 3 ноября 2026. Общие права на каталог сервисным аккаунтам не выдаются.

Источник: https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier.

## Что сохраняется

- Все ответы пяти этапов, входной результат и незавершённый тест с историей.
- Положение в заданиях и завершённые этапы.
- Для каждого ролика: ID источника, секунда, длительность, отметка завершения и время обновления.
- Версия сохранения и ID операции, чтобы безопасно повторить отправку после обрыва связи.

Видео и задания завершаются независимо. Переход к концу ролика не считается доказательством просмотра всех его фрагментов. Позиция обновляется примерно раз в 15 секунд, при паузе и завершении, поэтому при резком закрытии устройства возможна потеря последних секунд просмотра.

Коды имеют 128 случайных бит; в базе хранится хеш кода, а не его исходный текст. Сервер выдаёт отдельные временные сессии. Сессия хранится в sessionStorage и заканчивается при закрытии браузерной сессии; при повторном входе используется тот же код. На общих компьютерах нужно выходить из профиля. Коды выдаются наставником через приватный CSV, не в публичном интерфейсе. Отключение ученика отзывает доступ и существующих сессий.

При двух одновременно открытых устройствах используется проверка версии. Более старый вариант не перезаписывает новый: интерфейс предлагает сначала сохранить локальную копию, затем открыть облачную. Ответы без интернета временно остаются на устройстве и отправляются после восстановления связи. Неудача локального кеширования видна пользователю. Полный сброс очищает текущее сохранение ответов, но не удаляет служебную запись ученика и резервные копии провайдера.

## Локальная проверка

~~~sh
mkdir -p private
ORIENTA_DB_PATH=private/progress.sqlite npm run admin -- provision --count 3 --output private/codes.csv
ORIENTA_DB_PATH=private/progress.sqlite ORIENTA_ALLOWED_ORIGINS=http://127.0.0.1:5173 npm run server:dev
~~~

В другом терминале:

~~~sh
VITE_PROGRESS_API_URL=http://127.0.0.1:8787 npm run dev -- --host 127.0.0.1
~~~

Коды берутся из private/codes.csv. Эта папка исключена из Git и не должна попадать в публичный каталог сайта. Для выгрузки:

~~~sh
ORIENTA_DB_PATH=private/progress.sqlite npm run admin -- export --output private/results.csv
~~~

CSV имеет UTF-8 BOM и разделитель «;» для Excel, сохраняет ответы и прогресс видео. Коды доступа в выгрузку результатов не включаются. Для отключения доступа: npm run admin -- disable --id <UUID> с теми же серверными параметрами.

## Подключение облака

1. Создать отдельную YDB в режиме Serverless, регион Россия; не включать выделенную пропускную способность. Пилот использует обычную таблицу orienta_state и официальный ydb-sdk 5.11.1 через Table API. Закрытая операция initialize создаёт недостающую таблицу и проверяет схему; существующая чужая таблица сохраняется. Из ORIENTA_YDB_ENDPOINT берётся российский путь базы, запросы идут через grpcs://ydb.serverless.yandexcloud.net:2135. Document API в этом аккаунте возвращал 502 Canceled при чтении данных; обычный протокол прошёл настоящую проверку записи и транзакций.
2. Создать сервисный аккаунт функции с ydb.editor только на эту базу и отдельный аккаунт шлюза с functions.functionInvoker только на функцию. Постоянные ключи для выполнения функции не нужны: IAM-токен приходит в context.token. Доступ только к своей базе и функциям согласован владельцем при подключении.
3. npm run build:server собирает function.js, bootstrap.js и package.json с зависимостью ydb-sdk в dist-server, проверяет точки входа. Архивировать содержимое dist-server в корень ZIP. Ученическая функция: Node.js 22, точка входа function.handler, память 256 МБ, тайм-аут 30 секунд, без подготовленных экземпляров; тег orienta-pilot. Отдельная PRIVATE-функция orienta-admin: точка входа bootstrap.handler, ORIENTA_ADMIN_ENABLED=true, тот же доступ только к базе Orienta. Её вызывает оператор; allUsers и аккаунту шлюза доступ не назначается.
4. Задать серверные ORIENTA_YDB_ENDPOINT, ORIENTA_YDB_DRIVER=native, ORIENTA_YDB_TABLE=orienta_state, ORIENTA_ALLOWED_ORIGINS=https://apolon1795-max-orienta-c425.twc1.net. Ключи и параметры базы не помещать в VITE_*.
5. Подставить ID функции и аккаунта шлюза в server/gateway.template.yaml, создать API Gateway с тайм-аутом 35 секунд. В шаблоне явно задан payload_format_version: 1.0, где path содержит фактический HTTP-путь. Сервисная функция остаётся приватной. CORS допускает только адрес сайта; данные ученика доступны только по временной сессии.
6. Выпустить коды через административный CLI с короткоживущим IAM-токеном из окружения и серверными параметрами. Другой вариант — вызов закрытой orienta-admin из авторизованной консоли: {"operation":"initialize"} проверяет/создаёт таблицу orienta_state; {"operation":"provision","count":1} выдаёт код; {"operation":"export"} возвращает CSV; {"operation":"disable","learnerId":"<UUID>"} отключает ученика. Для пилота рекомендуется выдавать по одному коду за вызов. Перед повтором выдачи с неизвестным исходом проверить результат: автоматического повтора нет. Коды и ответы сохранять в приватные файлы, не в логи CI и не в репозиторий.
7. В Timeweb выбрать согласованный коммит ветки кандидата, Node.js 24, npm run build и каталог dist. Старый шаблон Angular с путём dist/orienta/browser для текущего React/Vite-кода не подходит. Добавить VITE_PROGRESS_API_URL=https://<gateway>.apigw.yandexcloud.net/api и реальные VITE_LESSON_1_VIDEO…VITE_LESSON_5_VIDEO, затем пересобрать.
8. На тестовом ученике проверить реальное видео, паузу, продолжение на втором устройстве, ответы, конфликт, экспорт, выход и отзыв доступа. Только после этого выдавать коды группе.

SQLite применяется для локальных проверок или существующего VDS с постоянным диском. На App Platform контейнер пересоздаётся при деплое, и его локальные данные пропадают; там SQLite-файл хранить нельзя. Источник: https://timeweb.cloud/docs/apps/how-it-works.

API Kinescope: https://docs.kinescope.com/player-docs/embedding/iframe-api/ и https://docs.kinescope.com/player-docs/embedding/iframe-api-control-player/. YDB HTTP API: https://yandex.cloud/ru/docs/ydb/docapi/tools/aws-http. Интеграция шлюза: https://yandex.cloud/ru/docs/api-gateway/concepts/extensions/cloud-functions.

## Граница текущей проверки

Проверены настоящая локальная SQLite, HTTP API, две браузерные сессии, перезагрузка, временная потеря сети, конфликт, личные коды, отзыв сессии и CSV. В автоматических браузерных тестах API Kinescope имитируется: реальные ссылки на пять уроков ещё ожидаются.

В облаке создана orienta-pilot: Serverless, Running, Россия, 10 RU/с, выделенная пропускная способность 0, объём до 1 ГБ. Сервисные аккаунты не имеют ролей на каталог. Серверу выдан ydb.editor только на эту базу; шлюзу — functions.functionInvoker только на orienta-progress. Обе функции и API Gateway развёрнуты; закрытая orienta-admin отклоняет анонимный вызов с 403. Рабочая таблица orienta_state прошла проверку чтения, записи, двух конкурирующих транзакций и повторного подключения. Ограниченный аккаунт функции подтвердил доступ к ней.

Через публичный шлюз проверены личные коды, восстановление ответов/частичного теста/позиции урока в другой сессии, конфликты, повтор одной операции, изоляция учеников, CORS, выход, отзыв доступа оператором и приватная CSV-выгрузка. Использованы только синтетические тестовые данные; ученик для предпросмотра сброшен после проверки. Публикация сайта фиксируется в PR и отчёте проверки.

Для совместимости сохранён драйвер ORIENTA_YDB_DRIVER=document и server/ydb-table.json. У него другая схема таблицы. Прежняя тестовая документная таблица orienta сохраняется отдельно от рабочей orienta_state.
