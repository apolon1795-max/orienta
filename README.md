# Orienta — Путь Героя

Игровой маршрут профориентации: пять ситуаций и четыре архетипа, гайд персонажа, пять этапов курса и Профкарта Героя. Сохранена существующая визуальная система: тёмный фон, золотые и фиолетовые акценты, карта пути и иллюстрации персонажей.

## Локальный запуск

Нужен Node.js 24.

~~~sh
npm install
npm run dev
~~~

Перед первым запуском скрипт сохраняет 38 исходных PNG из ссылок проекта в public/images. Повторный запуск использует локальную копию. Если хостинг изображений недоступен, npm run assets нужно повторить после восстановления доступа. Исходные URL записаны в data/assets.json; новые иллюстрации не генерировались.

## Проверки и сборка

~~~sh
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:browser
npm run test:browser:cloud
npm run build:server
~~~

npm test проверяет миграцию, этапы, резервные копии, профкарту, доступ по личному коду, изоляцию учеников, реальные HTTP-запросы к временной базе, конфликты версий и повторную отправку после обрыва связи. Браузерные сценарии проверяют полный пятиэтапный маршрут и продолжение с другого устройства. Свидетельства и снимки: output/playwright и output/cloud-browser. Kinescope в автоматическом тесте заменён имитацией его API; реальные ролики проверяются отдельно после получения ссылок. GitHub Actions сохраняет output, dist, dist-server и package-lock.json как артефакт orienta-verification.

Готовая статическая сборка — dist. VITE_BASE_PATH по умолчанию равен ./ для размещения в корне домена или подкаталоге. Существующий сайт — https://apolon1795-max-orienta-c425.twc1.net на Timeweb App Platform. Для пилота созданы YDB Serverless, Cloud Functions и API Gateway в России; сервер использует официальный SDK и сериализуемые транзакции Table API. Инструкция и границы проверенного — docs/pilot-hosting.md. Ветка сама по себе не обновляет работающий сайт.

## Ответы и сохранение

Версия данных — 3. Без VITE_PROGRESS_API_URL ответы, прогресс видео и незавершённый тест хранятся в текущем браузере. С настроенным API ученик входит по личному коду наставника и продолжает с другого устройства. Принимаются резервные копии версий 2 и 3; недостающие новые задания добавляются к прежним ответам. В хабе можно скачать или загрузить JSON. Импорт сначала предлагает подтверждение и скачивает текущий прогресс. Сброс требует подтверждения; повторный тест сохраняет ответы курса, полный сброс очищает весь маршрут и синхронизирует пустое сохранение.

Старый игровой архетип и ранее сохранённый вывод переносятся. Старые флаги трёх несвязанных модулей не считаются прохождением новых заданий без самих ответов. При повреждённом JSON исходная строка сохраняется в appState_ru_recovery, если хранилище доступно.

Облачное сохранение подтверждается ответом сервера и номером версии. При конфликте двух устройств отправка останавливается: перед открытием облачной версии скачивается текущая локальная копия. Незавершённая отправка хранится в кеше ученика и повторяется после восстановления связи; повтор одного запроса не создаёт лишнюю версию. Вход выдаёт временную сессию в sessionStorage; код ученика в браузере не сохраняется. При выходе кеш этого ученика очищается, а несохранённые ответы предварительно скачиваются файлом. Старое общее локальное сохранение не подмешивается в облачный профиль и не показывается до входа. Существующий анонимный прогресс можно перенести через заранее скачанную резервную копию.

server/admin.mjs выдаёт коды и экспортирует результаты в приватный CSV для Excel. Для настройки через консоль Яндекса есть отдельная закрытая функция bootstrap.handler: создание документной таблицы, выдача кодов, экспорт и отключение доступа. Она включается только явной серверной настройкой и защищается платформенным IAM; шлюзу учеников не выдаётся право её вызова. Административные операции не доступны через публичный API. Реальное подключение и выпуск кодов настоящих учеников проверяются отдельно. Постоянные облачные ключи и коды учеников в репозиторий и VITE_* не помещаются.

## Профкарта и ИИ

Основная профкарта собирается из ответов всех пяти этапов: выбранные профессии, самоанализ, ценности, три будущих подарка, навыки, работа мечты, профессиональные интересы, мотиваторы и план профессиональной пробы. Она доступна без внешнего ИИ; её можно скачать текстом или распечатать в PDF.

Дополнительный ИИ-разбор подключается через авторизованный API прогресса: сервер берёт сохранённые ответы, вызывает ProxyAPI / GPT-4o mini и сохраняет кэш в YDB. Кнопка появляется только при серверном aiAvailable=true. Секрет и явное включение задаются на Cloud Function; VITE_AI_PROXY_URL и прежние Google-переменные не используются. Есть защита от повторных генераций, предел 100 запросов на ключ за пилот и 3 на ученика за сутки UTC, проверка актуальности ответов и ошибок провайдера. Ошибка не подменяется готовым «ИИ-выводом». Настройка, порядок выпуска и ограничения обработки данных — [docs/ai-integration.md](docs/ai-integration.md). В рабочей публикации интеграция пока не активирована.

## Пятиэтапная программа

Задания сопоставлены с подробными авторскими страницами Notion. XP, ранги за XP и «Формула» убраны по позднему авторскому решению. Два итоговых опросника включают 12 утверждений интересов (0–2, по два на направление) и 10 вопросов мотивации с исходными весами по 12 шкалам. Суммы считаются из ответов; равенство на границе топ-2 и топ-3 показывается явно. Валидированная диагностика не заявляется.

Для пяти этапов VITE_LESSON_N_VIDEO принимает ссылки просмотра/встраивания Kinescope или прямые MP4/WebM. Плеер запоминает позицию примерно раз в 15 секунд, при паузе и завершении; повторное открытие незавершённого видео продолжает просмотр. Субтитры Kinescope задаются в самом Kinescope, VITE_LESSON_N_CAPTIONS используется для прямых файлов. Ролик доступен во время заданий и после завершения этапа. Завершение видео учитывается отдельно от выполнения задания; оно не доказывает просмотр каждой секунды. Замена видео по ID начинает отдельный прогресс. Пока ссылки пусты, показаны инструкции. Следующий этап открывается после выполнения предыдущего; недельное расписание пока не согласовано.
